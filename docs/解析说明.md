# 总体思路：先读"图纸"，再读"数据"

解析分两步，顺序不能反：

```
第1步：读 .cfg  →  得到一份"解读说明书"
         （有几个通道、每个通道叫什么、原始整数怎么换算成电压电流、
           采样率多少、从什么时刻开始、dat 是哪种编码）
第2步：读 .dat  →  按说明书把二进制/文本切成一堆数字
         （并结合说明书换算成工程量）
```

**关键认知：cfg 的行数是不固定的。** 第 2 行告诉你"有 6 个模拟量 + 4 个开关量"，所以第 3~12 行是通道定义，第 13 行才是系统频率。你不能跳到固定行号去读，必须从第 1 行一行一行往下走，中间维护一个"当前读到第几行"的游标。这是解析器最核心的结构。

# 一、.cfg 逐行解析

先看一份完整的 1999 版样例（数值我做了简化，只为讲结构）：

```
STATION_A,DFR-01,1999                                    ← 行1
10,6A,4D                                                 ← 行2
1,Ia,A,LINE1,A,0.0122,0,0,-32767,32767,400,1,P           ← 行3  模拟通道1
2,Ib,B,LINE1,A,0.0122,0,0,-32767,32767,400,1,P           ← 行4  模拟通道2
3,Ic,C,LINE1,A,0.0122,0,0,-32767,32767,400,1,P           ← 行5  模拟通道3
4,Ua,A,LINE1,V,3.357,0,0,-32767,32767,110000,100,P       ← 行6  模拟通道4
5,Ub,B,LINE1,V,3.357,0,0,-32767,32767,110000,100,P       ← 行7  模拟通道5
6,Uc,C,LINE1,V,3.357,0,0,-32767,32767,110000,100,P       ← 行8  模拟通道6
1,TRIP,A,LINE1,0                                         ← 行9  开关量1
2,CLOSE,A,LINE1,0                                        ← 行10 开关量2
3,52a,A,LINE1,0                                          ← 行11 开关量3
4,52b,A,LINE1,0                                          ← 行12 开关量4
50                                                       ← 行13 系统频率 Hz
1                                                        ← 行14 采样率段数 nrates
4000,8000                                                ← 行15 采样率4000Hz，到第8000点为止
01/03/2026,09:15:23.000000                               ← 行16 第一个采样点的时刻
01/03/2026,09:15:23.125000                               ← 行17 触发（故障）时刻
BINARY                                                   ← 行18 dat 文件类型
1                                                        ← 行19 时间倍数 timemult
```

## 行 1：厂站名, 装置标识, 版本年份

**这一行决定了后面所有行的字段数量，是解析的第一步，也是最重要的一步。**

判定规则很简单——**数逗号**：

| 字段数 | 含义 |
|---|---|
| 2 个 | 1991 版（1991 版没有版本年份字段） |
| 3 个 | 第 3 个是版本年份，值是 1991 / 1999 / 2013 |

这里有个现场坑：**很多录波器写的版本年份不规范**，实测出现过 `2000`、`2001`（IEC 版的年份）这类值。所以不要用 `if rev_year == 1999` 这种精确判断，要用 `>= 1999` 的区间判断，并且对认不出来的值记警告、按 1999+ 的规则继续解析，而不是直接报错退出。

## 行 2：总通道数, 模拟量数, 开关量数

格式是 `10,6A,4D`——数字后面跟一个字母 `A`（Analog）或 `D`（Digital）。注意有些厂家偷懒把字母省了，写成 `10,6,4`，所以解析时要把尾部字母剥掉再转数字。

**校验点**：`总通道数` 应该等于 `模拟量数 + 开关量数`。真实文件里偶尔对不上，对不上时以 `模拟量 + 开关量` 为准（因为后面的行数是按这两个数排的），记一条警告。

## 通道定义行：字段数和版本相关

这是版本差异最大的地方：

| | 1991 版 | 1999 / 2013 版 |
|---|---|---|
| **模拟通道行** | 10 个字段 | 13 个字段 |
| **开关量通道行** | 3 个字段 | 5 个字段 |

**模拟通道（13 字段版）逐字段含义：**

| # | 字段 | 含义 | 用途 |
|---|---|---|---|
| 1 | `An` | 通道序号 | **别信它**，用行顺序 |
| 2 | `ch_id` | 通道名称 | 显示 + 通道识别 |
| 3 | `ph` | 相别（A/B/C/N 或空） | 判断是 A 相还是 B 相 |
| 4 | `ccbm` | 所属线路/间隔 | 多条线路时区分通道 |
| 5 | `uu` | 单位（V/kV/A/kA 或空） | 归一化单位 |
| 6 | `a` | 比例系数 | **换算的核心** |
| 7 | `b` | 偏移系数 | 换算的核心 |
| 8 | `skew` | 通道时偏（µs） | 一般 0，可忽略 |
| 9 | `min` | 原始值下限 | 校验 + 判缺失值 |
| 10 | `max` | 原始值上限 | 校验 + 判缺失值 |
| 11 | `primary` | 一次侧额定值（CT/PT 变比分子） | 一次/二次值换算 |
| 12 | `secondary` | 二次侧额定值（变比分母） | 一次/二次值换算 |
| 13 | `PS` | `P` 或 `S` | 声明 a/b 换算出来的值是一次值还是二次值 |

1991 版就是少了最后 3 个字段（`primary`、`secondary`、`PS`），前 10 个含义完全相同。**所以你只需要写一套解析逻辑，判断"这行有 10 个还是 13 个字段"就行**——不要为两个版本写两套代码。

实战要点：
- 第 1 个字段（通道序号）现场经常乱写（从 0 开始、跳号、重复），**一律忽略，用读取顺序当序号**。
- 第 5 个字段（单位）经常是空的，或者厂家乱填，不能全指望它。
- `ch_id` 里**可能含空格**（比如 `I a`），切分时不要顺手 strip 掉内部空格，只在两头 strip。
- `ch_id` 可能**重复**，不能拿它当唯一键。

**开关量通道（5 字段版）**：`序号, 名称, 相别, 线路, 常态值`。最后那个"常态值"是 0 或 1，表示这个开关量在**正常运行**时是分还是合，用来判断变位方向。1991 版少了 `相别` 和 `线路` 两个字段。

## 采样率段

```
1              ← nrates：有几段采样率
4000,8000      ← 采样率 4000 Hz，到第 8000 个采样点为止
```

真实录波经常有两段：故障前用低频（比如 1000Hz）省空间，故障后用高频（比如 4000Hz）看清细节。这会写成：

```
2
1000,2000
4000,10000
```

意思是：第 1~2000 点按 1000Hz 采样，第 2001~10000 点按 4000Hz 采样。**`endsamp` 是"该速率最后覆盖到的采样点编号"，是累计编号，不是每段的点数**——这里特别容易算错。

注意 `nrates = 0` 是一种合法情况，表示"文件里不声明采样率"，这时候只能靠 dat 里每个采样点自带的时标来建时间轴。

## 起止时间行

格式是 `日/月/年,时:分:秒.微秒`，**注意是"日/月/年"，不是"月/日/年"**。

但现场文件经常是 `月/日/年`，而且大部分日期前 12 天两种读法都合法，无法从格式上区分。实用的判别方法：

- 第一个数字 > 12 → 一定是"日/月/年"
- 两个数字都 ≤ 12 → 无法确定，按标准按"日/月"解析，但记一条警告
- 保险做法：提供配置项让用户指定日期格式，或者在导入界面上把解析出的时间显示出来让人确认一次

秒的小数位：1991/1999 是微秒（6 位），**2013 允许纳秒（9 位）**。

## 行 18：dat 文件类型

取值有四种：

| 值 | 含义 |
|---|---|
| `ASCII` | 文本格式，最直观，体积大 |
| `BINARY` | 每个采样值 2 字节整数 |
| `BINARY32` | 每个采样值 4 字节整数（**2013 才有**） |
| `FLOAT32` | 每个采样值 4 字节浮点数（**2013 才有**） |

**这个值决定了第 2 步怎么切 dat**，所以必须解析出来。

## 行 19：timemult（时间倍数）

1999 版新增的字段，单位是微秒，缺省值 1。它只用来换算 dat 里每个采样点自带的时标：`时刻(秒) = 时标 × timemult × 10⁻⁶`。

1991 版没有这一行，直接按 1 处理。

## 2013 版多出来的两行

2013 版在 `ft` 之后还多了两行时间信息：

```
BINARY
1
-5h30,-5h30      ← time_code, local_code（时区偏移）
B,3              ← tmq_code, leapsec（时间质量、闰秒）
```

解析时如果版本是 2013，多读这两行；如果是 1999，读到 `timemult` 就结束。**不管是哪个版本，都要容忍文件末尾有多余的空行或空白字符。**

# 二、.dat 解析

## ASCII 格式

最简单，一行一个采样点：

```
1,0,-1234,567,-1190,32100,-500,31800,1,0,1,0
2,250,-1240,570,-1188,32150,-505,31790,1,0,1,0
```

字段顺序是：

```
采样号, 时标, 模拟量1, 模拟量2, ..., 模拟量6, 开关量1, 开关量2, ..., 开关量4
```

注意两点：

1. **ASCII 格式里开关量是不打包的**，一个通道占一列，值就是 0 或 1。这和二进制完全不同。
2. 时标的单位是微秒（乘 timemult 得真实时间）。

## BINARY 格式（现场最常见）

这是二进制，不是文本，**必须按字节切，不能按行读**。每条记录的布局是固定的：

```
偏移   长度   内容
─────────────────────────────────────────────
0      4     采样号              uint32，小端
4      4     时标（µs）          uint32，小端
8      2     模拟通道1 的值       int16，小端
10     2     模拟通道2 的值       int16，小端
12     2     模拟通道3 的值       int16，小端
14     2     模拟通道4 的值       int16，小端
16     2     模拟通道5 的值       int16，小端
18     2     模拟通道6 的值       int16，小端
20     2     开关量1~16 的位打包   uint16，小端
─────────────────────────────────────────────
合计   22 字节 / 每条记录
```

**字节序是小端（低字节在前）**。这一点标准原文我没能拿到（标准是收费的），但四个主流开源解析器（python-comtrade、comtrade-rs、GSF、pycomtrade）全部按小端实现，可以认为是事实标准。稳妥起见，解析后做一次范围校验就能立刻发现问题：**如果字节序搞错了，解出来的值会远远超出 cfg 里 `min`/`max` 声明的范围**，这是一个零成本的自动检查。

**记录长度的通用公式**：

```
BINARY   记录长度 = 8 + 2 × 模拟量数 + 2 × ceil(开关量数 / 16)
BINARY32 记录长度 = 8 + 4 × 模拟量数 + 2 × ceil(开关量数 / 16)
FLOAT32  记录长度 = 8 + 4 × 模拟量数 + 2 × ceil(开关量数 / 16)
```

**开关量的位打包规则**：每 16 个开关量塞进一个 2 字节的字，**最低位（bit 0）对应这组里的第 1 个通道**，依次往上。不足 16 个的高位补 0。比如开关量 1 合上、其他分，这个字就是 `0x0001`；开关量 3 合上就是 `0x0004`。

这个打包是新手最容易出错的地方——很容易误以为一个通道占一个字节。

**用文件大小做校验（强烈建议实现）**：

```
期望记录数 = 各采样率段的 endsamp 的最大值
期望文件大小 = 期望记录数 × 记录长度
```

拿实际的 dat 文件大小一比，如果差了几个字节（通常是末尾多了换行符，或者少了一条记录），立刻就能定位到"通道数解析错了 / 版本判错了 / 文件被截断了"。这个检查只需要一行代码，能挡掉现场一大半的疑难文件。

## BINARY32 / FLOAT32

记录布局和 BINARY 一样，只是每个模拟量从 2 字节变成 4 字节。

- **BINARY32**：4 字节有符号整数，同样要 `a × raw + b` 换算。
- **FLOAT32**：4 字节 IEEE 754 浮点数，**通常已经是工程量，a/b 往往是 1 和 0 或者干脆是垃圾值**。所以对 FLOAT32 类型要特别处理，不要盲目套用 a/b。

# 三、原始值 → 工程量（换算）

dat 里存的是 ADC 采到的原始整数（比如 -32767 到 32767），要变成"多少安、多少伏"：

```
工程值 = a × 原始值 + b
```

a 和 b 是 cfg 里给的，它们的来源是：

```
a = (值域上限 - 值域下限) / (raw_max - raw_min)
b = 值域上限 - a × raw_max
```

含义就是"把原始整数线性映射到物理量程"。

**然后是 PS 字段决定这个工程值是一次值还是二次值：**

- `PS = P`：算出来的已经是一次值，直接用
- `PS = S`：算出来的是二次值，要乘 `primary / secondary` 才是一次值

比如 CT 是 400/1，`PS = S`，算出来是 0.85，那一次值就是 `0.85 × 400 = 340 A`。

⚠️ **这里有一个必须知道的重要坑**：上面这条"ASCII 数据也要用 a/b 换算"的规则，是标准的主流解读，四个开源解析器全都是无条件换算的。但**现场确实存在直接写工程量的 ASCII 文件**，如果无条件换算，就会**被二次换算**，结果是静默出错——不报错，就是数值差了几百倍。

判别方法：**拿 dat 里的数值范围去对比 cfg 里的 `min`/`max`**。

- 数值落在 `[min, max]` 区间内 → 是原始值，需要换算
- 数值远小于 `min`/`max`（比如 min/max 是 ±32767，数据却在 ±400 附近）→ 很可能已经是工程量，不该再乘 a

调研的结果是：**没有任何一个开源解析器做了这个自动判别**，所以遇到这类文件它们都会出错。建议你们把它做成一个显式选项（自动探测 + 允许用户手动覆盖 + 在日志里记录走了哪条路径），这反而是你们产品相对开源方案的一个实打实的优势。

# 四、时间轴怎么建

有两种机制，优先级是**采样率段优先，时标兜底**：

**方式一（优先）：按采样率段推算**

```
第 1~2000 点   ： t = (n - 1) / 1000
第 2001 点起   ： t = 2000/1000 + (n - 2000) / 4000
```

注意第二段要**接着第一段的末尾时间继续累加**，不能让时间倒回去。

**方式二（兜底）：按每个采样点的时标**

```
t = 时标 × timemult × 10⁻⁶    （单位：秒）
```

什么时候用方式二：`nrates = 0`（文件不声明采样率）、或者该采样点的时标是"缺失值哨兵"（见下）。

**无论用哪种，都要做单调性检查**：如果算出来的时间轴出现回退或跳变，标记这条录波"时间轴不可信"并记警告，而不是默默产出一份错位的数据。

# 五、完整流程（伪代码）

```
def parse_comtrade(cfg_path, dat_path):

    # ── 阶段1：读 cfg ──────────────────────────
    lines = read_text_with_encoding_fallback(cfg_path)   # GBK / UTF-8 都试

    line1 = split(lines[0])
    version = 1991 if len(line1) < 3 else parse_version(line1[2])
    # 2 字段 → 1991；否则看 rev_year，用 >= 1999 的区间判断

    fields2 = split(lines[1])
    total, na, nd = parse_channel_counts(fields2)

    cursor = 2
    analogs = [parse_analog_line(lines[cursor + i], version)
               for i in range(na)]
    cursor += na
    digitals = [parse_digital_line(lines[cursor + i], version)
                for i in range(nd)]
    cursor += nd

    line_freq   = lines[cursor]; cursor += 1
    nrates      = lines[cursor]; cursor += 1
    rate_segs   = [parse_pair(lines[cursor + i]) for i in range(nrates)]
    cursor += nrates
    start_time  = parse_datetime(lines[cursor]); cursor += 1
    trigger_time= parse_datetime(lines[cursor]); cursor += 1
    data_type   = lines[cursor].strip().upper(); cursor += 1
    # 2013: 再读 time_code/local_code 和 tmq/leapsec 两行
    timemult    = float(lines[cursor]) if version >= 1999 else 1.0

    # ── 阶段2：校验 ────────────────────────────
    check(total == na + nd)
    check(cfg 与 dat 的基名一致、dat 存在)
    expected_records = max(endsamp for _, endsamp in rate_segs)
    expected_size = expected_records * record_length(na, nd, data_type)
    warn_if(abs(actual_dat_size - expected_size) > 容差)

    # ── 阶段3：读 dat（按 data_type 分支）──────
    if data_type == 'ASCII':
        raw, timestamps = read_ascii(dat_path, na, nd)
    elif data_type == 'BINARY':
        raw, timestamps = read_binary(dat_path, na, nd, value_bytes=2)
    elif data_type == 'BINARY32':
        raw, timestamps = read_binary(dat_path, na, nd, value_bytes=4)
    elif data_type == 'FLOAT32':
        raw, timestamps = read_binary_float(dat_path, na, nd)

    # ── 阶段4：换算工程量 ──────────────────────
    for ch in analogs:
        ch.values = ch.a * raw[ch.index] + ch.b
        if ch.PS == 'S':
            ch.values *= ch.primary / ch.secondary     # 二次 → 一次
        ch.values = normalize_unit(ch.values, ch.uu)   # kV→V, kA→A
        flag_missing_values(ch, raw[ch.index])         # 哨兵值单独标记

    # ── 阶段5：建时间轴 ────────────────────────
    t = build_time_axis(rate_segs, timestamps, timemult)

    # ── 阶段6：组装 + 诊断 ─────────────────────
    return Recording(meta=..., channels=analogs + digitals,
                     time_axis=t, diagnostics=warnings)
```

# 七、实战坑清单（按踩到概率排序）

**1. 缺失值哨兵**
标准定义了"这个采样点没采到"的特殊值，必须识别出来单独处理，否则它会在波形上变成一个巨大的尖峰，把峰值和有效值全带偏：

- ASCII：1999+ 用 `99999`，1991 用空值
- BINARY：1999+ 用 `0x8000`（-32768），1991 用 `0xFFFF`
- BINARY32：`0x80000000`
- FLOAT32：最负的浮点数

**2. 编码问题**
1991/1999 的 cfg 名义上是 ASCII，但国内的录波器经常把中文厂站名按 **GBK** 写进去，用 UTF-8 读会得到乱码或直接抛异常。**解析器必须做编码兜底：先试 UTF-8，失败后试 GBK/GB18030。** 只有 2013 的 `.cff` 才保证是 UTF-8。

**3. 字节序**
按小端解析，然后用 `min`/`max` 做范围校验。

**4. 日期格式 日/月 vs 月/日**
见上文，无法完全自动判定，要给用户一个确认机会。

**5. 通道名重复 / 含空格 / 空白**
不能拿名字当唯一键，不能随意 strip 内部空格。

**6. 通道序号字段不可信**
一律用读取顺序当索引。

**7. a 和 b 是垃圾值**
现场出现过 a=0、b=0 或者离谱的值。校验：`a == 0` 要报警告（除了 FLOAT32 类型）。

**8. 声明点数 ≠ 实际点数**
cfg 说 8000 点，dat 里只有 7950 点，或者多出几条。以实际能读到的为准 + 告警，不要直接崩溃。

**9. 采样率多段**
`endsamp` 是累计编号不是段内点数，这是最容易算错的地方。

**10. 文件末尾多余字节**
dat 末尾经常多一个换行符，导致 `文件大小 / 记录长度` 除不尽。做校验时留容差。

# 八、这些工作对应到你们项目的哪几条需求

| 上面讲的内容 | 对应需求编号 |
|---|---|
| 版本兼容、字段数自适应 | P-01、P-02、NF-31 |
| 通道解析、采样率、时间轴 | P-03、P-04、P-05 |
| 统一内部数据对象 | P-06 |
| 异常文件不崩溃、输出错误原因 | P-07、F-04、F-05、NF-12 |
| 单位归一化、一次值换算 | E-01、E-02 的精度前提 |
| 缺失值、字节序、编码兜底 | 无对应编号，但直接决定 E-01「符合人工计算规律」能不能过 |

最后一行值得注意：**需求文档里没有一条明确要求处理"缺失值哨兵"和"编码兜底"**，但这两件事不做，验收时用客户的真实文件一测就会暴露。建议把这两条补进 P 模块的需求里，同时补上"记录长度与文件大小必须交叉校验"这条——它是排查现场疑难文件最省力的手段。
